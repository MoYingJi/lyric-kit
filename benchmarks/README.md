# 歌词时间查询基准

运行 `pnpm build`，然后执行 `node benchmarks/sync.mjs`

基准使用 300 行及 5000 行歌词，每行间隔 1000ms、持续 1500ms，模拟相邻行重叠。每轮执行 20,000 次跳转查询，先预热，再取 5 轮耗时中位数，并校验新旧查询结果的校验和。完整逐项一致性由 `tests/sync-index.spec.ts` 验证。

本地 Windows / Node.js 24.13.0 的一次测量：

| 行数 | 线性查询 | 索引查询 | 一次构建 |
| ---- | -------- | -------- | -------- |
| 300  | 3.72ms   | 1.45ms   | 0.14ms   |
| 5000 | 65.05ms  | 3.68ms   | 0.88ms   |

这些是整个 20,000 次查询的耗时，不是单帧耗时。结果受运行环境影响，常规歌曲的绝对收益较小。

`createActiveLyricFinder` 保留时间快照，构建为 O(n)，快照占用约 24n 字节的时间数组。查询通过两次二分缩小范围，再逐项检查候选行；长时间重叠覆盖大量歌词时仍可能扫描 O(n)。输入须按开始时间排序，修改原数据后必须重新构建，不使用隐式缓存。
